# FedEdge-IoT: Methodology Document

## Synthetic Dataset Generation

### Feature Definitions

| Feature | Unit | Normal Range | Fault Range |
|---------|------|-------------|-------------|
| `rms_vibration` | g (gravitational acceleration) | 0.5 – 1.2 | 1.8 – 5.0 |
| `peak_vibration` | g | 0.7 – 2.0 | 2.5 – 8.0 |
| `vibration_variance` | dimensionless | 0.03 – 0.08 | 0.25 – 0.55 |
| `dominant_frequency` | Hz | RPM/60 ± noise | RPM/60 × 1.4 ± noise |
| `temperature` | °C | 58 – 72 | 78 – 95 |
| `rpm` | revolutions/minute | stable at set point | ±15% of set point |

All values are **synthetic** — they are statistically plausible but do not represent
measurements from real industrial equipment.

### Non-IID Distribution Design

Each node is assigned a `machine profile` that controls:
- **rpm_mean**: average rotational speed
- **rpm_std**: variability in speed
- **noise**: amplitude multiplier for all features

Additionally, each node has an independent **fault_rate** (e.g., node_0 = 10%, node_4 = 45%).
This creates a non-IID data distribution across nodes, a key real-world challenge for
federated learning.

### Train / Test Split Strategy

- **Training data**: generated by `generate_node_datasets()` with seed `S`
- **Test (holdout) data**: generated by `generate_holdout_test_set()` with seed `S+999`

Using a different seed for test data prevents any possibility of test records appearing
in any node's training data. Both datasets are generated independently from the same
underlying distributions (Normal and Fault).

The test set uses a fixed 30% fault rate and the "medium_machine" profile to represent
a neutral, balanced evaluation standard.

## FedAvg Mathematical Formulation

### Standard FedAvg (McMahan et al., 2017)

Given:
- K participating nodes
- Node k has n_k training samples
- Node k's updated local weights after local training: **w**_k
- Total samples: N = Σ n_k

**Aggregation formula:**

$$\mathbf{w}_{global} = \frac{1}{N} \sum_{k=1}^{K} n_k \cdot \mathbf{w}_k$$

Equivalently:

$$\mathbf{w}_{global} = \sum_{k=1}^{K} \frac{n_k}{N} \cdot \mathbf{w}_k$$

This is a **sample-weighted average** — nodes with more training data contribute
proportionally more to the global model.

### Per-layer averaging

The MLP model has weight matrices **W** and bias vectors **b** for each layer.
FedAvg averages each element independently:

$$W^l_{global} = \sum_{k} \frac{n_k}{N} W^l_k, \quad b^l_{global} = \sum_{k} \frac{n_k}{N} b^l_k$$

This requires all nodes to use **identical architectures** (same shapes for W and b).

### Round structure

```
for round r = 1 to R:
    1. Coordinator sends w_global to all K nodes
    2. Each node k:
         local_data = node k's private dataset
         w_k = local_SGD(w_global, local_data, epochs=E)
    3. Nodes send w_k and n_k to coordinator
    4. Coordinator computes w_global = FedAvg({w_k, n_k})
    5. Evaluate w_global on held-out test set
```

## Communication Accounting

### Definitions

- **Model size** (bytes) = number of float64 parameters × 8
  - Architecture 6→32→2: params = (6×32 + 32) + (32×2 + 2) = 224 + 66 = 290 params
  - Model size ≈ 290 × 8 = 2,320 bytes ≈ 2.3 KB

- **Raw record size** = 80 bytes per CSV row (6 features × ~10 chars + label + delimiters)

### Federated communication per experiment

| Traffic type | Formula | Description |
|-------------|---------|-------------|
| Initial broadcast | model_bytes × N | Round 0 distribution |
| Per-round download | model_bytes × N × R | Server → nodes |
| Per-round upload | model_bytes × N × R | Nodes → server |
| **Total** | model_bytes × N × (1 + 2R) | Full experiment |

### Centralized communication per experiment

| Traffic type | Formula | Description |
|-------------|---------|-------------|
| Raw data upload | records × 80 bytes | ALL node records → server |

### Communication savings formula

$$\text{Savings (\%)} = 100 \times \left(1 - \frac{\text{federated\_bytes}}{\text{centralized\_bytes}}\right)$$

**When savings increase:**
- Larger training datasets (centralized cost grows, federated stays constant per round)
- Fewer federated rounds
- Smaller model (lower per-round federated cost)
- More nodes (both increase proportionally)

## Model Architecture

```
Input Layer:   6 features (rms_vibration, peak_vibration, vibration_variance,
                           dominant_frequency, temperature, rpm)
               
Hidden Layer:  32 neurons, ReLU activation
               
Output Layer:  2 classes (Normal=0, Fault=1), Softmax

Total params:  (6×32 + 32) + (32×2 + 2) = 224 + 66 = 290 parameters
Model size:    290 × 8 bytes = 2,320 bytes ≈ 2.3 KB
```

Using scikit-learn's `MLPClassifier` with `warm_start=True` for incremental training.

## Evaluation Metrics

### Classification metrics (macro average)

$$\text{Precision} = \frac{1}{|C|} \sum_{c \in C} \frac{TP_c}{TP_c + FP_c}$$

$$\text{Recall} = \frac{1}{|C|} \sum_{c \in C} \frac{TP_c}{TP_c + FN_c}$$

$$\text{F1} = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

For predictive maintenance, **Recall for Fault class** is especially important:
a missed fault (false negative) is more costly than a false alarm.

### Inference latency

Measured by timing 100 single-sample predictions and averaging,
discarding the first 5 warm-up runs. Reported in milliseconds.
This is a **local computation latency** measure, not end-to-end system latency.
